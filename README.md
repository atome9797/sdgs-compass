# SDGsコンパス (SDGs Compass)

**企業と学生をつなぐ、SDGs特化型マッチングプラットフォーム.**
기업이 SDGs 과제(챌린지)를 내면 학생이 기획서로 응모하고, 심사·수상 기록이 **SDG별 Impact Index(레이더 차트)** 와
**위·변조를 확인할 수 있는 디지털 증명서**로 남아요. 그 실적을 본 기업이 인재를 스카우트·채용하면
**기업은 상금·연구 의뢰비를 학생·연구자에게 직접 전액 지급하고, 그 10%(최저 ¥9,000)를 수수료로 운영사에 따로 내는**(인턴 채용은 무료, 운영사는 돈을 맡지 않아요) 구조예요 → [docs/fees.md](docs/fees.md).
정체성은 **「提案で選ばれるSDGsインターン」** — 경력이 아니라 제안으로 뽑히고, 인턴십으로 실현해요(홈 화면의 한 줄 소개).

> 🎮 **게임 테마(2026-11-14, #37)** — 앱의 맨 위 제목은 **「勇者さま、助けてください！」**(한국어 「용사님 구해주세요!」)예요.
> 기업은 퀘스트를 의뢰하는 NPC(의뢰인), 학생은 퀘스트를 깨는 용사예요. 과제 = クエスト, 팀 = パーティ, 제출 = 「クエスト達成！」, 레벨 대신 스킬(수상 1건 = SDG 번호가 붙은 스킬 1개, #38),
> 상품 보상 = 「報酬アイテム」(수상하면 「〇〇を手に入れた！」, 카드뉴스에는 「提供」 표시). 화면 구성은 그대로예요 → [docs/quest.md](docs/quest.md)

- **일본어 / 한국어 둘 다**: 웹·앱을 처음 열면 **언어를 먼저 고르고**(기기 언어를 미리 강조만 해요), 언제든 머리글의 **日本語 | 한국어** 토글로 바꿔요.
  발표는 일본어로, 개발·확인은 한국어로 같은 앱을 써요.
- **세 가지 역할(웹)**: 언어 다음에 **학생·개인(B2C)** / **기업·기관(B2B)** / **연구자(대학원생)** 중 고르고, 머리글의 역할 칩을 누르면 다시 역할 선택으로 가요. 한 앱에서 세 쪽 흐름을 모두 시연할 수 있어요(모바일 앱은 학생·기업 두 역할).
- **연구 의뢰(웹 데모)**: 기업이 표창·채택한 학생 아이디어를 실현하려고 대학원생 연구자에게 **연구를 의뢰**하고(의뢰비는 기업이 정해요), 연구자가 맡아서 성과(보고서·데이터)를 보내면 기업이 확인하고 의뢰비를 **직접 전액** 지급해요(데모는 기록만). 운영 수수료는 의뢰비의 10%(최저 ¥9,000)를 기업이 따로 내요. 끝나면 기업과 연구자가 서로 평가해요 → [docs/research.md](docs/research.md).
- **기업 네트워크(웹 데모, 2026-11-08)**: 이 앱에서 약속대로 지급하고(상금 · 연구 의뢰비) 거래 상대(학생 · 연구자 · 기업)에게 평가받은 기업은 **신뢰 기업**이 되어, 다른 신뢰 기업에 시제품 · 제조 · 물류 같은 일을 **지명**하거나 **공개 모집**으로 의뢰해요. **수수료는 없어요**(신뢰 기업의 특전). 아이디어를 실현하는 흐름의 마지막 단계(제조·판로)를 앱 안에서 잇고, 상대의 지급 실적과 평가를 보고 직접 고를 수 있어요 → [docs/network.md](docs/network.md).
- **서버 없이 전체 흐름이 돌아가는 데모**: 샘플 데이터(모두 가상)로 챌린지 출제 → 응모 → 심사 → 수상 → Impact → 증명서 → 스카우트 → 채용 → 수수료까지 한 바퀴를 돌려 볼 수 있어요. 화면마다 `DEMO` 배지가 붙어요.
- **SNS 피드**: 학생은 수상·제출·참가 실적을 **자랑 글**로, 기업은 SDGs 활동을 **홍보 글**(항상 `PR` 표시)로 올려요. 이메일 주소·전화번호처럼 보이는 글자는 올릴 수 없고, 공식 SNS(X·Instagram·Facebook 중 하나) 게시 신청은 하루 제한 없이 회사마다 한 달에 4번까지 받고, 날짜는 기업이 내일부터 30일 뒤까지에서 골라요. 예정일·게시료는 쓴 기업에게만 보이고, 다른 사람에게는 실제로 게시된 뒤 「公式SNSで見る ↗」 링크가 보여요 → [설계](docs/sns-feed.md).
- **운영자 화면(웹 전용 · 데모)**: 이용 현황 · SNS 지표 · 수지·자금 시뮬레이션을 한 곳에서 봐요. 이용 현황은 앱의 데모 데이터를 세고, SNS 지표는 사람이 옮겨 적은 숫자(CSV 가능)를 주별로 보여 주고, 수지·자금은 입력한 가정으로 흑자 전환 시기·자금 잔액·손익분기 기업 수와, 운전자금 N개월분(기본 3)을 남기고 그 기 이익의 나머지를 학생에게 돌려주는 **학생 환원**(켜고 끌 수 있어요)을 계산해 두 시나리오를 겹쳐 비교해요. 로그인 없는 데모이고 입력은 이 브라우저에만 저장돼요 → [docs/admin.md](docs/admin.md).
- **수수료 = 상금·연구 의뢰비의 10%(최저 ¥9,000, 2026-11-08)**: 기업은 최우수상 팀에 상금을, 연구자에게 의뢰비를 **직접 전액** 지급하고, 수수료는 운영사에 **따로** 내요. 운영사는 돈을 맡지 않아서 학생 화면 「受け取った賞金」은 받은 상금(과 흑자 뒤의 운영사 특별상)의 **기록**만 보여 줘요(잔액·출금 없음). 인턴 채용은 무료, 기부는 기업이 원할 때만 → [docs/fees.md](docs/fees.md) (이전의 リワード残高 설계는 [docs/rewards.md](docs/rewards.md)).
- **웹(Next.js) + 모바일(Expo / React Native)** 이 한 저장소(npm 워크스페이스 모노레포)에 있고, 규칙·계산·화면 모델·문구는 `packages/core`, 샘플 데이터·저장은 `packages/data`를 함께 써요.
  그래서 어느 쪽에서 해도 결과와 문구가 같아요. ([SchedulAI](https://github.com/atome9797/SchedulAI) 와 같은 방식)
- **DB 설계까지 검증**: PostgreSQL 16 스키마(표 68개 · 뷰 8개)를 실제 DB에 올려 시험 7개 파일(구조·규칙·흐름·앱↔DB 대조·운영·SNS 피드·リワード残高)을 통과시켰어요. ERD 는 그 DB에서 읽어 자동으로 만들어요. (돈의 표는 아직 이전 설계 — 2026-11-08 수수료 모델로 옮기는 일은 [docs/fees.md](docs/fees.md) 「남은 일」)
- **GitHub Actions**: CI(웹·앱·DB 검사), GitHub Pages 웹 데모 자동 배포, Android 데모 APK 자동 빌드(+ Releases 업로드), 마일스톤을 닫으면 태그·Release 자동 생성.
- **QR 로 바로 체험**: 발표 당일에는 QR 코드를 공개하고, 청중이 휴대폰으로 읽어 설치 없이 웹 데모에 들어와요 → [열기](#열기).

| --- | --- | --- |
| 하는 일 | 관심 SDGs·스킬에 맞는 챌린지를 찾고, 팀을 꾸려 기획서를 내요 | SDGs 과제를 출제하고, 응모작을 심사·수상·채용해요 |
| 얻는 것 | 수상·참가 실적이 **Impact Index · 배지 · 디지털 증명서 · SNS 카드뉴스**로 남고, 피드에 **자랑 글**로 올릴 수 있어요 | 과제 해결 아이디어, 검증된 인재, **ESG 성과 리포트 · 실천 마크**, 피드의 **홍보 글** |
| 핵심 화면 | 홈 · 피드 · 검색 · 챌린지 상세 · 기획서 제출 · Impact · 증명서 · 카드뉴스 · 메시지 | 대시보드 · 피드 · 새 챌린지 · 응모자·심사 · 인재 검색·스카우트 · ESG·실천 마크 |
| 돈 | 무료 · 상금을 기업에게서 **직접 전액** 받아요(「受け取った賞金」에 기록) | 상금·연구 의뢰비의 **10%(최저 ¥9,000)** 를 수수료로 따로 · **인턴 채용 · 신뢰 기업끼리의 업무 의뢰는 무료** · 기부는 원할 때만 |

- **왜 플랫폼을 거치나요?** 학생의 SDGs 활동 이력이 한곳에 쌓이고(포트폴리오), 기업은 같은 자리에서 아이디어·인재·ESG 성과를 얻어요.
  기업은 언제 무엇에 돈을 내는지(상금·연구 의뢰비의 10%) 미리 알 수 있고, 받는 사람의 몫은 줄지 않아요.
- **실천 마크**(일본어 화면은 「取組みマーク」)는 기업의 SDGs 활동을 앱이 정한 **독자 기준**으로 보여 주는 표시예요 — **★5 만점 · 0.5 단위**(달성도 10점마다 ★0.5, 100점 ★5.0, 10점 미만은 未取得)이고, 기업 ESG 화면뿐 아니라 **학생이 보는 피드·챌린지 카드·챌린지 상세의 회사 이름 옆**에도 「SDGs取組みマーク ★4.5」처럼 보여요(누르면 안내, #35). 국가·자치체·국제연합의 인증이 아니고, UN·SDGs 공식 로고는 쓰지 않았어요(번호를 넣은 색 타일만 사용).
  마크 화면에는 그 안내가, 첫 화면·설정·(PC) 사이드바에는 "이 앱은 유엔의 승인을 받은 것이 아니에요" 고지가 항상 보여요. 코드·DB 이름은 예전 그대로 `cert_*` 예요.
- **학생은 무엇을 얻나요?** 무료로 쓰고, 활동이 **기록과 디지털 증명서(QR)** 로 남아요. "SDGs 활동만으로 받는 전국 공통 장학금"은 조사에서 확인되지 않았고, 가장 가까운 실제 제도는 대학의 활동 장려 제도(예: 専修大学 自己啓発奨学生)예요.
  그래서 앱은 장학금을 주지 않고, **신청할 때 쓸 활동 기록·증명서**를 갖추는 데까지가 범위예요. Impact 화면의 「申請用のまとめを作る」로 기간을 골라 활동·증명서를 **A4 한 장(인쇄·PDF)** 으로 정리할 수 있어요 → [docs/student-merit.md](docs/student-merit.md).
- **실적은 스킬로 보여요(#38 — 레벨은 없어요).** 수상 1건이 **SDG 번호가 붙은 스킬** 1개가 되고, 마이 Impact(용사의 스테이터스) · 전투 화면 · 카드뉴스 · 활동 기록 요약에 보여요. 포인트는 SDG 레이더 차트와 정렬에 쓰는 내부 점수이고 돈과는 관계없어요(바꿀 수 없어요). 기업의 인재 검색에는 「スキル 2」(= 수상 수)가 보여요. 단, **기업 심사의 보너스만은 숫자로 보여요**(#30): 기업이 매긴 점수 3개(創造性·実現可能性·SDGs貢献度, 5점 만점)와 코멘트가 학생의 마이 Impact 「挑戦中のクエスト」 카드에 공개되고, 평균에 따른 보너스가 「+64pt をマイImpactに反映」처럼 보여요(최대 80pt — 레이더 차트에 쓰는 같은 포인트예요). 가장 낮은 항목이 하나뿐이면 「次に伸ばすポイント：実現可能性」처럼 알려 줘요. 기업 심사 화면에도 "점수와 코멘트는 학생에게 공개되고 Impact 포인트에 더해진다"는 안내가 있어요.
- **상금은 기업이 직접 지급해요(2026-11-08).** 기업은 과제를 낼 때 상금을 **걸기만** 하고(돈은 오가지 않아요), 최우수상을 정하면 그 팀에 **직접 전액** 지급해요(데모는 지급으로 기록). 운영사는 상금의 10%(최저 ¥9,000)를 수수료로 따로 청구하고, 돈을 맡지 않아요. 흑자가 된 뒤에는 각 기 말에 **운전자금 3개월분**(그 기 경비 + 매출원가의 3/12)을 남기고 **그 기 경상이익 중 남는 금액 전부**를 미리 공개한 기준(수상·제출 실적 — 작업 시간·양이 아니에요)으로 **운영사 특별상**으로 드려요 → [docs/fees.md](docs/fees.md).
- **대시보드 숫자 카드를 누르면 그 목록으로**(#33): 募集中の課題 → 課題の管理 · 総応募者数 → 응모자(모든 과제) · 審査待ち → 응모자 「審査待ち」 · 採用（インターン） → 응모자 「採用」 · 手数料の累計 → お支払い（手数料）. 응모자 화면에는 「すべての課題」와 상태 필터(すべて · 審査待ち · 審査済み · 受賞 · 採用)가 있고, 웹은 주소(`/b2b/applicants/?id=all&status=submitted`)에 남아서 새로고침해도 그대로예요. 카드 숫자(샘플 응모자 수·지난 매칭)와 목록 수가 다르면 이유가 한 줄로 나와요.
- **제출 버전은 「第1版」 / 「1차 제출」**(#34): 예전의 `v1` 칩이 레벨(Lv.1)로 읽혀서 바꿨어요(다시 내면 第2版 / 2차 제출).

### 발표 당일: QR → 웹

1. 슬라이드에 QR(`docs/qr/web-demo.png`)과 주소를 함께 보여 줘요. **슬라이드 높이의 1/3 정도로 크게** 넣고, QR 둘레의 흰 여백은 자르지 마세요(어두운 배경 위에서도 읽혀요).
2. 청중이 휴대폰 카메라(iPhone 은 카메라 앱, Android 는 카메라나 Google 렌즈, 일본에서는 LINE 의 QR 리더도 많이 써요)로 읽으면 웹 데모가 열려요.
3. QR 주소에 `?lang=ja` 가 붙어 있어서 **일본어로 바로 시작**해요(언어 선택을 건너뛰고 역할 선택부터 — 그 기기에 한국어가 저장돼 있어도 일본어가 우선). 머리글의 `日本語 | 한국어` 로 언제든 바꿀 수 있어요.
4. 발표자는 자기 폰(또는 노트북)으로 아래 [10분 발표용 시연 순서](#10분-발표용-시연-순서)대로 보여 주고, 청중은 각자 폰에서 따라 눌러 봐요.

### 첫 화면과 역할 전환

1. **언어 선택** — `日本語` / `한국어` 큰 버튼 두 개. 기기 언어는 미리 강조만 하고 자동으로 고르지 않아요. 한 번 고르면 기기에 기억해요.
   주소에 `?lang=ja`(또는 `?lang=ko`)가 붙어 있으면 이 화면을 건너뛰고 그 언어로 시작해요 — 저장된 언어보다 우선하고, 그 값을 기억해요(발표용 QR 이 이 주소예요).
2. **역할 선택** — "학생·개인(B2C)" / "기업·기관(B2B)" / "연구자(대학원생)" 카드(연구자는 웹만). 데모에서는 로그인 없이 바로 들어가요.
3. 머리글 오른쪽의 **日本語 | 한국어** 토글로 언어를, **역할 칩**(누르면 역할 선택 화면)이나 설정의 단추로 역할을 언제든 바꿔요. 설정 화면의 **데모 초기화**는 샘플 데이터와 설정을 지우고 1번 화면부터 다시 시작해요.
4. **운영자 화면(데모, 웹 전용)** — 역할 선택 화면 아래의 `運営者画面（デモ）`(한국어 `운영자 화면(데모)`) 링크로 들어가요. 역할 선택은 건너뛰고, 위쪽 탭으로 이용 현황 · SNS 지표 · 수지·자금을 오가요. 학생·기업 화면의 메뉴에는 나오지 않아요 → [docs/admin.md](docs/admin.md).

### 10분 발표용 시연 순서

11/14 아이디어 피치회(10분 발표 → 플랜 컨설턴트 피드백, 그다음 주 2차 심사)의 발표 대본과 **같은 순서**예요(#9). 발표자 PC 의 웹 데모로 일본어 화면을 보여 주고, 시연은 QR 공개 40초 + 2분 30초예요(나머지는 사업계획 슬라이드 약 6분과 여유 약 40초). 대본·타임테이블·장애 대응은 저장소 밖 발표 자료(발표 대본·당일 운용)에 있어요.

| 순서 | 시간 | 역할 | 보여 줄 것 |
| --- | --- | --- | --- |
| D0 | 0:40 | — | DEMO 슬라이드의 **QR 공개** → 청중이 휴대폰으로 접속(설치·로그인 없이 일본어 역할 선택부터) — 그동안 「勇者（学生・個人）」를 고르라고 안내 |

| D6 | 0:20 | 기업 → 학생 | 피드(회사 이름 옆 「SDGs取組みマーク ★2.5」 — 학생 화면에도 같은 마크): 수상 건의 PR 글 + 공식 SNS 게시 신청(「公式SNSへの掲載を申し込む」 체크 · Instagram · 날짜는 처음 골라진 내일 그대로 — 「◀ 날짜 ▶」 가운데 칸에 그 달의 남은 횟수 「残り n/4回」) → (시간이 있으면) 왼쪽 메뉴 「研究・企業の依頼」 → 맨 위 칩 「企業ネットワーク」에서 우리 회사의 신뢰 실적(신뢰 기업끼리는 수수료 없이 의뢰) → 역할을 학생으로(역할 칩 → 「学生・個人」) → 마이 Impact 「企業からの審査結果」(점수·코멘트·+pt — 한 번 보여 주기) → (시간이 있으면) 수상 실적으로 자랑 글 |

시간이 모자라면 이 순서로 줄여요: ① D6 통째로(한마디로 대신) ② D4 의 변조 테스트 ③ D5 의 심사 점수 입력(줄여도 「審査を保存」만은 눌러요 — 그래야 학생 화면에 점수·+pt 가 나와요. 기본값 3·3·3 이면 「総合 3.0/5.0 · +48pt」) ④ D5·D6 를 말로만(슬라이드 쪽에서 줄이는 순서는 발표 대본에). QR 접속이 늦어도 40초가 지나면 D1 로 넘어가요.

### 발표 전 점검표 (5분)

실제 폰에서의 실행은 자동 검사로 확인되지 않아요. 발표 전날 한 번 해 보세요.

- [ ] 슬라이드의 QR 을 **iPhone 과 Android 의 카메라**로 읽는다 → 웹 데모가 열리고 언어 선택 없이 **일본어 역할 선택**부터 나온다(QR 주소의 `?lang=ja`) (LINE 앱의 QR 리더로도 열어 본다)
- [ ] 발표장과 같은 조건(와이파이 또는 모바일 데이터)에서 첫 화면이 몇 초 안에 뜬다
- [ ] 프로젝터·모니터에 띄운 QR 을 **맨 뒤 자리**에서도 읽을 수 있다 (크기·밝기·화면 비율 확인)
- [ ] 역할 선택 → 학생(B2C) 홈이 일본어로 보인다

- [ ] 역할 칩으로 기업(B2B) 대시보드에 갔다가 학생 홈으로 돌아온다

### 9. 학생 메리트 (활동 증명서 · 대학 제도 연계)

학생은 **무료**로 쓰고, 활동이 **기록과 디지털 증명서(QR)** 로 남아요. 그 증명서를 대학의 활동 장려 제도(예: 専修大学 自己啓発奨学生)에 **신청할 때 쓰는 자료**로 삼는 것이 앱이 그리는 그림이고, 앱이 장학금을 주지는 않아요(상금은 기업이 직접 지급하고, 흑자 뒤에는 운영사 특별상 — [docs/fees.md](docs/fees.md)). 조사 결과·신청 과정·출처는 [docs/student-merit.md](docs/student-merit.md).

| 학생이 얻는 것 | 상태 |
| --- | --- |
| 무료 이용 · Impact(스킬·SDG 레이더·배지) · 퀘스트 전투 화면(WebGL) · 디지털 증명서(SHA-256 + QR, 진위 확인 ✓ / 변조 ✗) · 확정한 활동 기록·증명서는 수정 불가 | **지금** (시제품에서 동작) |
| 신청용 요약 「申請用のまとめ」 — 기간(전체 · 최근 1년 · 최근 6개월)을 골라 활동 · SDGs · 증명서 ID·QR · 고지를 A4 한 장으로 (웹은 인쇄·PDF, 앱은 글로 공유) | **지금** (시제품, #22) |
| 받은 상금(기업이 직접 지급)·운영사 특별상의 기록 「受け取った賞金」 | **데모** (실제 송금 없음 — 운영사는 돈을 맡지 않아요) |
| 대학·재단 제도 일람 · 결과 자기 신고 | **구상** (화면 없음) |
| 대학이 앱의 증명서를 증빙으로 인정하는지 | **미확인** (대학에 확인할 일) |

## ERD (DB 설계)

`db/schema.sql` 은 PostgreSQL 16 용 스키마예요. 기능명세(SPEC-2026-SDGS-01)의 기능 ID(F-101 ~ F-703)와 1:1 로 대응하도록 설계했어요.
앱 데모는 이 DB 에 직접 연결하지 않지만(샘플 데이터 + 기기 저장), **앱의 도메인 타입(`packages/core/src/domain.ts`)과 같은 모양**이라 실서비스에서는 같은 규칙을 서버가 돌려줘요.

설계 원칙:

- **규칙은 DB 도 한 번 더 지켜요**: 앱이 막아도 서버·관리자 도구·직접 SQL 로 우회되지 않게 `CHECK`·복합 외래 키·트리거로 같은 규칙을 넣었어요 (아래 [표](#db-가-지키는-규칙)).
- **앱 ↔ DB 대조 시험**: 수수료·레벨·인증 점수·증명서 해시 같은 계산과 SNS 글의 글자 수·연락처 검출·공식 게시 날짜·입력 검사는 `packages/core` 의 값이 기준이고, `scripts/gen-db-reference.ts` 가 만든 정답표(`db/tests/golden.sql`)로 DB 계산이 같은지 CI 가 확인해요.
- **한 번 기록하면 못 고치는 것**: 제출 버전, 활동 기록, 디지털 증명서, 감사 로그는 `UPDATE`/`DELETE` 를 트리거로 막아요(증명서의 폐기 표시만 예외).
- **일본어/한국어**: 이름·문구 열은 `name_ja`/`name_ko` 로 두고, 사용자가 쓴 글의 번역은 `content_translations` 에 캐시해요.
- **날짜는 일본 시간(JST) 기준**: 수령증 번호·스카우트 하루 한도는 `jst_date()` 로 계산해요.
- 아래 그림과 표 설명은 **실제 DB 에서 읽어 자동으로 만든 것**이에요(`npm run erd`). 스키마를 바꾸고 README 를 안 고치면 CI 가 실패해요.

> **DB 의 돈 표는 아직 이전 설계예요.** 아래 ERD 의 `matches` 수수료·기부 열, `donations`, ⑨ #25 리워드 표(`wallet_*` · `prize_deposits` · `withdrawal_requests`)는 2026-11-08 이전 모델이에요. 앱은 이미 직접 지급 모델(채용 무료 · 상금·연구 의뢰비의 10% 수수료)이고, DB 를 옮기는 일은 [docs/fees.md](docs/fees.md) 「남은 일」에 있어요.

**한 방향으로만 의존해요**: `apps/*` → `packages/data` → `packages/core`. 화면은 얇게 두고(`selectXxx(상태, 언어)` → 그리기, `dispatch(액션)`), 규칙·문구·계산은 모두 `packages/core` 에만 있어요.
그래서 웹과 앱이 같은 결과를 내고, 규칙 시험(`*.test.ts`)은 화면 없이 돌아요.

## CI / 배포 (GitHub Actions)

이 저장소는 **공개(public)** 라서 GitHub 서버의 실행 시간이 무료예요. SchedulAI 의 `ci.yml` 구조(단계마다 `run-step.sh` 로 실패 원인을 주석으로 남기기)를 따르되 self-hosted 실행기는 쓰지 않아요.

| 워크플로 | 언제 | 하는 일 |
| --- | --- | --- |
| `ci.yml` | main·`feat/**` 푸시, PR, 수동 | **db**: PostgreSQL 16 에 스키마·시드를 올려 시험 7개 파일 → 생성 파일(`seed.sql`·`golden.sql`)·README ERD 최신 여부<br>**web**: react 한 벌 · lint(web, core·data) · 테스트(core·data·web) · 타입 검사 · 빌드 · Pages 용 정적 내보내기<br>**mobile**: 타입 검사 · lint · Jest · `expo install --check` · `expo-doctor` · `expo prebuild` · `expo export`(iOS+Android 번들)<br>**lockfile**: `package-lock.json` 이 없으면 한 번 만들어 main 에 커밋 |
| `pages.yml` | main 푸시(웹·공용 패키지 변경), 수동 | 웹 정적 내보내기(`NEXT_PUBLIC_BASE_PATH=/<저장소 이름>`) → GitHub Pages 배포 |
| `android-apk.yml` | main 푸시(앱·공용 패키지 변경), 수동 | `expo prebuild` → `./gradlew :app:assembleRelease`(기본 arm64) → 서명 확인 → Artifacts 와 **Releases `demo-latest`** 에 `sdgs-compass-demo.apk` 업로드 |
| `release.yml` | **마일스톤을 닫을 때**, 수동 | 마일스톤 이름이 `v0.3 …` 처럼 버전으로 시작하면 태그 `v0.3.0` 과 GitHub Release 를 만들어요. 노트는 `docs/releases/v0.3.0.md` 가 있으면 그 파일, 없으면 마일스톤의 목표와 닫힌 이슈 목록이에요 ([자세히](#릴리스-마일스톤을-닫으면)) |

### 릴리스 (마일스톤을 닫으면)

마일스톤 이름이 `v0.3 …` 처럼 버전으로 시작하면, 그 마일스톤을 **닫을 때** `release.yml` 이 닫은 순간의 main 커밋에 태그 `v0.3.0` 을 붙이고 GitHub Release 를 만들어요(누가 닫든 같아요). 규칙은 [SchedulAI](https://github.com/atome9797/SchedulAI) 의 `release.yml` 과 같아요.

1. 릴리스 노트를 `docs/releases/v0.3.0.md` 로 먼저 main 에 올려요(닫은 이슈 목록을 넣어요). 파일이 없으면 마일스톤의 "목표" 줄과 닫힌 이슈 목록으로 채워요.
2. 마일스톤을 닫아요 (Issues › Milestones › Close milestone).
3. Actions › **Release (마일스톤을 닫으면)** 실행이 성공했는지, Releases 에 새 항목이 생겼는지 확인해요.

- 이미 닫은 마일스톤은 Actions › **Release (마일스톤을 닫으면)** › Run workflow 에 마일스톤 번호(마일스톤 주소 끝의 숫자)를 넣어서 만들어요. 태그는 그 마일스톤을 닫을 때까지의 main 커밋에 붙어요.
- 같은 태그가 이미 있으면 건너뛰어요(다시 열었다 닫아도 두 번 만들지 않아요). "Latest" 표시는 가장 높은 버전에 있고, APK 를 올리는 `demo-latest` 는 계속 사전 릴리스(Pre-release)예요.

### GitHub Pages 웹 데모 켜기

처음 한 번만 저장소 설정이 필요해요:

1. 저장소 **Settings › Pages** 를 열어요.
2. **Build and deployment › Source** 를 **GitHub Actions** 로 바꿔요.
3. **Actions › Deploy web demo (GitHub Pages) › Run workflow** 를 눌러요(또는 main 에 푸시).

배포가 끝나면 https://atome9797.github.io/sdgs-compass/ 에서 열려요. 설정 전에는 이 워크플로의 deploy 작업만 실패하고(요약에 안내가 나와요) CI 에는 영향이 없어요.

### Android 데모 APK 받기

1. 저장소의 **Releases › demo-latest** 에서 `sdgs-compass-demo.apk` 를 내려받아요(항상 최신 main 빌드예요).
   직접 주소: `https://github.com/atome9797/sdgs-compass/releases/download/demo-latest/sdgs-compass-demo.apk`
2. 휴대폰에서 파일을 열고 **출처를 알 수 없는 앱 설치**를 허용해요.
3. 서버 없이 혼자 실행돼요. 첫 화면에서 언어와 역할을 골라요.

- 기본 빌드는 `arm64-v8a`(대부분의 실제 폰)예요. 안드로이드 에뮬레이터(x86_64)용은 Actions 에서 수동 실행할 때 `abis` 에 `arm64-v8a,x86_64` 처럼 적어요.
- Expo 템플릿의 공개 `debug.keystore` 로 서명한 **데모용**이라 스토어 배포용이 아니에요.
- 요청하는 권한은 **인터넷(React Native 기본) 하나**예요. 저장소 읽기·쓰기, 진동, 다른 앱 위에 표시 권한은 `apps/mobile/app.config.ts` 의 `blockedPermissions` 로 막아 두었고, 빌드할 때마다 CI 가 `aapt2` 로 확인해요(남아 있으면 빌드 실패). 앱 코드는 서버와 통신하지 않아요.
- Actions › Android APK (demo) 실행의 Artifacts(`sdgs-compass-demo-apk`)에도 14일간 같은 파일이 있어요.

### package-lock.json 에 대해

이 저장소를 처음 만든 환경에서는 npm 레지스트리에 접속할 수 없어서 `package-lock.json` 을 미리 만들 수 없었어요.
그래서 처음 main 에 푸시됐을 때 CI 의 `lockfile` 작업이 한 번 만들어서 `chore: package-lock.json 생성 (CI)` 커밋으로 올렸고, 지금은 모든 워크플로가 `npm ci` 로 같은 버전을 설치해요.
로컬에서 이어서 작업한다면 먼저 `git pull` 해서 이 커밋을 받으세요. 잠금 파일이 이미 있으면 `lockfile` 작업은 아무것도 하지 않아요.

## 데모의 한계와 알려진 점

- **서버·DB 연결 없음**: 화면의 데이터는 샘플(가상)이고 웹은 `localStorage`, 앱은 `AsyncStorage` 에 저장돼요. DB 스키마는 설계·검증용이에요.
- **없는 것**: 소셜/이메일 로그인과 본인 확인, 결제·실제 송금·청구(수수료는 계산과 기록만), 푸시/카카오/SMS 알림, 관리자(승인·신고) 화면, 1:1 대화·면접 일정 화면, Q&A 게시판.
- **운영자 화면은 로그인 없는 웹 데모예요.** 이용 현황은 앱의 데모 데이터를 세고, SNS 지표는 사람이 옮겨 적은 숫자(외부 SNS 의 API 연동 없음)이며, 수지·자금은 입력한 가정을 계산하는 시산이에요(세금·감가상각·운전자본 증감·이자·계절성 제외, 예측·투자 판단이 아님). 학생 환원은 "운전자금 N개월분을 남기고 그 기 경상이익의 나머지"라는 규칙만 계산하고, 세금 · 실제 배분 기준 · 지급 방법은 별도예요. 입력은 이 브라우저(`localStorage`)에만 저장되고, 실서비스의 로그인·관리자 권한·DB 집계는 아직 없어요 → [docs/admin.md](docs/admin.md).
- **SNS 피드는 앱 안의 게시판이에요.** 실제 X·Instagram·Facebook 계정으로 올리는 기능, 이미지·영상 업로드, 댓글·팔로우·알림, 관리자 검수·신고 화면은 없어요. 공식 SNS 게시 신청은 X·Instagram·Facebook 중 하나이고(YouTube 는 영상 채널이라 신청 대상이 아니에요) '예정'(기업이 고른 날짜)까지만 하고 실제 게시와 게시료 정산은 하지 않아요. 운영자가 "게시 완료 + 게시글 주소"로 바꾸는 화면은 서버 버전에서 만들어요(데모에는 샘플 글 하나만 게시 완료로 들어 있어요). 글은 쓴 언어 그대로 보여요(자동 번역 없음).
- **파일 첨부는 업로드가 아니에요.** 웹은 진짜 파일 선택기(`<input type="file">`)로 고르거나 "샘플 기획서" 단추를 쓰는데, 파일의 **이름과 크기만** 읽고 내용은 읽지도 보내지도 않아요. 모바일 앱은 파일 선택기 없이 견본 파일 3개(마지막 하나는 일부러 형식이 틀린 파일) 중에서 골라요. 두 곳 모두 제출 수령증의 지문(SHA-256)은 파일 이름·크기·제목·요약·버전으로 만들어요.
- **디지털 증명서**의 해시 검증은 앱 안에서만 해요(블록체인 기록·외부 검증 서버 없음). 변조 시연은 "복사본을 고쳐서 검증 실패 확인"으로 보여 줘요.
- **돈은 기록만 해요.** 상금·연구 의뢰비는 기업이 상대에게 직접 지급하는 설계라 데모는 지급을 **기록**하고 수수료(10%, 최저 ¥9,000)를 **계산**만 해요 — 실제 결제·송금·청구는 없어요. 상금은 최우수상 1팀(데모에서는 제출자)에게만 가고, 팀 안의 나눔·상별 상금·원천징수는 아직 없어요. 샘플 내역 「運営からの特別賞（サンプル）」은 화면 예시예요(특별상은 흑자 뒤 기 말에 이익과 자금이 남을 때만 생겨요). 기업 간 업무 의뢰비도 기록만 해요. DB·운영자 수지 시뮬레이션은 아직 이전 모델이에요 → [docs/fees.md](docs/fees.md).
- **신뢰 기업과 평가는 데모 규칙이에요.** 기준값(약속대로 지급한 거래 1건 · 평가 1건 이상 평균 ★3.5 · 지급 지연 14일)은 데모용이고, 평가는 고치거나 지울 수 없고 이의 신청 · 운영자의 숨기기도 아직 없어요. 기업 간 의뢰의 취소 · 분쟁 · 계약 서면도 없어요 → [docs/network.md](docs/network.md).
- **학생 메리트의 신청용 요약은 시제품**(기간을 골라 A4 한 장으로 인쇄·PDF, 앱은 글로 공유)이고 **제도 일람·결과 자기 신고는 구상**이에요. 앱의 증명서·요약을 대학 제도에서 증빙으로 인정하는지는 확인 전이에요. 앱은 장학금을 지급하지 않고(상금은 기업이 직접 — 데모는 기록) 대학·재단과 제휴한 것도 아니에요 → [docs/student-merit.md](docs/student-merit.md).
- **팀 인원 · 세미나 이름은 웹 데모만 입력해요.** 모바일 앱의 제출 화면에는 아직 이 칸이 없어서 3명 · 세미나 없음으로 저장되고(모바일 새 과제의 모집 형태는 처음 값만 팀), DB 의 `proposals` 에 인원 · 세미나 열을 더하는 일은 다음이에요. 「ゼミで参加」는 학생이 적은 이름을 보여 줄 뿐, 대학 · 교수의 확인은 하지 않아요.
- **추천**은 규칙 기반 점수(관심 SDGs 우선순위 · 스킬 · 마감 임박도 · 상금)예요. 그래서 화면에는 「AI」라고 쓰지 않아요(「おすすめのクエスト」 / 「추천 챌린지」). 실서비스에서는 같은 입출력의 추천 모델로 바꿀 수 있어요.
- **번역**은 화면 문구(일본어/한국어 사전)만 해요. 사용자가 쓴 글의 자동 번역은 DB 의 `content_translations` 에 자리만 있어요.
- **실천 마크**(取組みマーク)는 독자 기준이에요. 국가·자치체·국제연합의 인증이 아니고, 마크 화면에 그 안내가, 첫 화면·설정·(PC) 사이드바에 "유엔 승인 아님" 고지가 항상 보여요. DB 표 이름(`cert_*`)과 ERD 의 표 설명은 예전 이름 '인증마크'를 그대로 써요. 별은 늘 마크 이름·숫자와 함께 보여서(스크린 리더 「SDGs取組みマーク 5段階中4.5」) 사용자 평점으로 읽히지 않게 했고, 「優良企業」 같은 말은 쓰지 않아요. 데모의 다른 회사 마크 값은 가상의 샘플이에요.
- **일본어 화면의 용어**: 기업이 내는 과제는 「課題」라고 써요(한국어 화면은 「챌린지」). 레벨 이름 「チャレンジャー」와 배지 이름 「チャレンジキング」은 고유한 이름이라 그대로예요.
- **날짜**는 앱을 여는 날을 "오늘"로 삼고 샘플 날짜를 그만큼 옮겨서, 언제 열어도 D-day 가 자연스러워요(`rebase`).
- iOS 설치 파일(IPA)은 만들지 않았어요. iPhone 은 웹 데모(홈 화면에 추가)를 쓰세요. Expo Go 로 여는 방법은 "실행하기 › 모바일"을 보세요.
- **실제 폰에서의 실행**은 자동 검사로 확인할 수 없어요. 앱은 CI(타입 검사·Jest·번들 내보내기·APK 빌드)와 같은 코드를 쓰는 웹 데모의 화면 점검까지만 확인했어요. 발표 전에 [발표 전 점검표](#발표-전-점검표-5분)대로 한 번 설치해서 눌러 보세요.

## 공개 저장소 안내

- 이 저장소는 **공개**예요. 공모전의 비공개 자료(기능명세서 원문, UI 가이드 이미지, 심사 관련 문서)는 넣지 않았고, 이름·기업·점수는 모두 가상의 샘플이에요.
- **UN SDGs 공식 로고·아이콘 이미지는 쓰지 않았어요.** 17개 목표는 공개된 색상값과 번호만으로 그린 타일이에요.
- 비밀 값(API 키·서명 키)은 필요 없고 저장소에도 없어요. `.gitignore` 가 `*.keystore`·`.env*` 를 막아요.

## 日本語の概要

**SDGsコンパス**は、企業が出すSDGs課題に学生が企画書で応募し、審査・受賞の実績が
**SDG別のImpact Index（レーダーチャート）** と **改ざんを検証できるデジタル証明書** として残る、企業と学生をつなぐマッチングプラットフォームです。
コンセプトは**「提案で選ばれるSDGsインターン」**。企業は賞金・研究依頼費を学生・研究者へ**直接、満額**支払い、当社はその**10%（最低9,000円）**を手数料として企業から別にいただきます（インターンの採用は無料、当社はお金を預かりません）。

- **日本語／韓国語の両対応**：初回起動時に言語を選び（端末の言語を事前に強調表示）、ヘッダーの「日本語 | 한국어」でいつでも切り替えられます。
- **3つの立場（Web）**：学生・個人（B2C）・企業・団体（B2B）・研究者（大学院生）を選択し、ヘッダーのチップで切り替えて、1つのアプリですべての流れをデモできます（モバイルアプリは学生・企業の2つ）。
- **発表当日はQRコードを公開**：スマホでQRコードを読み取ると、インストール不要でWebデモが開きます（日本語の利用タイプ選択から開始。入力内容は各自の端末にだけ保存されます）。
- **サーバー不要のデモ**：サンプルデータ（すべて架空）で、課題出題 → 応募 → 審査 → 受賞 → Impact → 証明書 → スカウト → 採用 → 手数料まで一巡できます。
- **SNSフィード**：学生は受賞・提出・参加の実績を「実績投稿」として、企業はSDGs活動を「PR投稿」（必ず「PR」表示）として投稿できます。メールアドレスや電話番号は書けません。公式SNS（X・Instagram・Facebookから1つ選択）への掲載申込みは、1社につき月4回まで（すべてのSNSの合計、1日あたりの上限はありません）で、掲載日は明日から30日後までの中から企業が選びます。掲載予定日と掲載料は投稿した企業だけに表示され、ほかの人には掲載後に「公式SNSで見る ↗」リンクが表示されます。
- **応募は1チーム3〜5人**：大学生・大学院生のチームが、1〜2か月を目安に企画書（課題の分析・解決策・実行計画と費用の見積もり）と発表資料で提案します。大学の授業・ゼミで取り組むチームは、応募のときにゼミ・授業名と指導教員を書けて、企業の応募者画面に「ゼミで参加」と表示されます。
- **学生のメリット**：学生・個人は無料で利用でき、活動の記録とQRコード付きのデジタル証明書（アプリ内で真偽を確認）が残ります。大学の活動奨励制度（例：専修大学の自己啓発奨学生）に申請するときの資料として、期間を選んで活動の記録と証明書をA4・1枚にまとめる「申請用のまとめ」（Webは印刷・PDF保存）を試作しました。大学側の取り扱いは未確認です。アプリが奨学金を出すことはありません（韓国語の詳細は [docs/student-merit.md](docs/student-merit.md)）。
- **企業ネットワーク（Webデモ）**：アプリの中で約束どおりに支払い（賞金・研究依頼費）、取引の相手（学生・研究者・企業）から評価された企業は「信頼企業」になり、信頼企業どうしで試作・製造・物流などの仕事を指名または公開募集で頼み合えます。手数料はかかりません（信頼企業の特典）。研究依頼が終わると、企業と研究者はお互いを評価します（韓国語の詳細は [docs/network.md](docs/network.md)）。
- **受け取った賞金（デモ）**：賞金は企業から最優秀賞のチームへ直接、満額で支払われ、学生の画面には受け取りの記録が残ります（当社はお金を預からないため、残高や出金はありません）。黒字化後は、各期末に運転資金3か月分を残した経常利益の残りを、事前に公開した基準（受賞・提出などの実績）で学生向けの特別賞として贈ります。デモでは実際の送金は行いません。実績はインパクトレベル（換金できません）で表示します（韓国語の詳細は [docs/fees.md](docs/fees.md)）。
- **運営者画面（ウェブのみ・デモ）**：利用状況・SNS指標・収支／資金シミュレーションを1か所で確認できます（入力はこのブラウザ内だけに保存され、ログインはありません）。
- **Web（Next.js）＋ モバイル（Expo / React Native）** を1つのリポジトリで管理し、ロジック・文言は共通パッケージを共有。DB設計（PostgreSQL、68テーブル）とER図も含みます。
- Android用デモAPKは[Releases](https://github.com/atome9797/sdgs-compass/releases/tag/demo-latest)、Web版は https://atome9797.github.io/sdgs-compass/ （初回のみ Settings › Pages › Source を「GitHub Actions」に設定）。
