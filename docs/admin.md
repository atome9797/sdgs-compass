# 운영자 화면 — 이용 지표 · SNS 지표 · 수지·자금 시뮬레이션

운영자가 ① 서비스가 얼마나 쓰이는지, ② SNS 반응이 어떤지, ③ 사업 수지·자금이 어떻게 흘러갈지를 한 곳에서 보는 **웹 전용 화면 3개**예요 (이슈 #16 · #17, v0.3).
앱(모바일)에는 없어요. 지금은 **데모**라서 로그인·관리자 권한이 없고, 입력한 숫자는 **이 브라우저 안에만** 남아요(서버로 보내지 않아요).

> ⚠️ ③은 **가정 숫자를 계산하는 시산 도구**예요. 예측·보증·투자 판단이 아니에요.
> 이 저장소(공개)의 샘플·시험·문서의 숫자는 **모두 가상**이에요. 실제 사업 계획의 숫자는 넣지 않아요 — 운영자가 자기 브라우저에서 입력하거나 JSON 파일로 가져와서 써요.

## 1. 한눈에 보기

| 화면 | 웹 주소 | 보는 것 | 숫자의 출처 | 이 브라우저에 남는 것 |
| --- | --- | --- | --- | --- |
| ① 이용 현황 | `/admin/` | 학생·기업·챌린지·응모·스카우트·매칭·피드의 지금 숫자, 기간별 추이, 숫자를 풀어 쓴 문장 | 앱의 데모 데이터(학생·기업 화면과 같은 값) | 없음(읽기만 해요) |
| ② SNS 지표 | `/admin/sns/` | X · Instagram · Facebook · YouTube 의 주별 추이, 최신 주 비교 | 운영자가 손으로(또는 CSV 로) 입력한 숫자 | 입력한 행 |
| ③ 수지·자금 | `/admin/finance/` | 흑자 전환 시기 · 자금 잔액 · 손익분기 기업 수 · 민감도 · 두 시나리오 겹쳐 비교 | 운영자가 입력한 가정 | 시나리오(최대 20개) |

- **들어가는 법**: 역할 선택 화면 아래의 「運営者画面（デモ）」(ko: 운영자 화면(데모)) 링크 한 곳뿐이에요. 학생·기업 화면의 탭·메뉴에는 두지 않았어요. 역할 선택은 건너뛰고, 위쪽 탭(이용 현황 · SNS 지표 · 수지·자금)으로 옮겨 다녀요.
- 모든 화면에 "데모 버전 화면이에요. 실제 운영에서는 로그인과 관리자 권한이 필요해요" 안내가 보여요. 문구는 일본어(기본)·한국어 둘 다 있어요.
- 모든 그래프에는 **"표로 보기"** 단추(같은 숫자의 표)와 스크린 리더용 설명이 있어요. 모바일 폭에서 누르는 곳은 44px 이상으로 점검했어요.

### 저장 위치

- `localStorage` 키 `sdgs-compass:admin:v1` 한 곳에 모아요(SNS 입력 행 · 시나리오 · 선택 상태). 학생·기업 화면의 데모 데이터와는 따로예요. 저장 모양의 버전이 다르면 읽지 않고 빈 상태로 시작해요.
- 저장소를 못 쓰는 브라우저(사생활 보호 모드 등)에서는 **화면을 닫을 때까지만** 남고, 화면에 그렇게 안내해요. 저장이 실패해도 입력한 값은 화면에 그대로 보여요.
- SNS 화면의 "입력을 모두 지우기"는 SNS 입력만 지우고, 시나리오는 ③에서 하나씩 지워요. 브라우저의 사이트 데이터를 지우면 모두 사라져요.

## 2. ① 이용 현황 (`/admin/`)

앱의 데모 데이터(`DemoState`)를 운영자가 보기 좋은 숫자로 세어요(`packages/core/src/adminUsage.ts`). 이 화면에서는 아무것도 바꾸지 않아요.

- **지어내지 않아요.** 날짜가 있는 기록(글 · 기획서 · 스카우트 · 팀원 모집 · 매칭 · 활동 기록)만 기간으로 묶어요. 날짜가 없거나 의미 있게 나눌 수 없는 것(학생 수 · 챌린지 상태 …)은 "지금 값"으로만 보여요. 기준일은 화면 위에 적혀요.
- **지금의 숫자** 12개: 학생(데모) · 기업(인증 완료) · 챌린지(모집 중·심사 중·마감) · 응모자 합계 · 기획서 제출(심사 완료·채용) · 수상 · 발행할 수 있는 증명서 · 스카우트(수락·읽음·거절) · 매칭 성사(수수료·기부) · 피드 글(학생 실적·기업 PR) · 좋아요 합계 · 공식 SNS 게시 신청(승인 전의 "예정").
- **기간(7·30·90일, 기본 30일)**: 글 · 기획서 · 스카우트 · 팀원 모집 · 매칭 · 활동 기록의 건수 추이. 7일은 하루씩, 30일은 5일씩, 90일은 10일씩 묶어요.
- **한 줄 읽기**: 숫자를 문장으로 풀어 줘요(예: 응모자가 가장 많은 SDG).
- 그 밖에 응모자가 많은 SDGs, 기획서 상태, 공식 SNS 게시 신청(SNS별), 챌린지별 표가 있어요.

## 3. ② SNS 지표 (`/admin/sns/`)

X · Instagram · Facebook · YouTube 의 분석 화면에 나오는 숫자를 **주 1회 사람이 옮겨 적어요**. 외부 SNS 에 연결하지 않아요(API 연동은 하지 않는 데모). 계산은 `packages/core/src/adminSns.ts`.

| 입력 | 뜻 | 규칙 |
| --- | --- | --- |
| 주 | 그 주의 월요일 | `YYYY-MM-DD` (CSV 에서 월요일이 아니면 오류로 알려 줘요) |
| SNS | X · Instagram · Facebook · YouTube | CSV 에서는 `x` `instagram` `facebook` `youtube` (`twitter` `ig` `fb` `yt` 도 읽어요) |
| followers | 팔로워 수 (YouTube 는 구독자 수) | 0 이상의 정수 (`1234` 또는 `1,234`, 상한 1조) |
| reach | 리치 = 표시된 횟수 (YouTube 는 조회수) | 0 이상의 정수 |
| engagement rate | 참여율 | 입력 칸은 0~100(%), CSV 는 `0.032` 또는 `3.2%`, 비우면 "모름" |
| link clicks | 링크 클릭 수 | 0 이상의 정수 |

- 같은 주·같은 SNS 를 다시 넣으면 **새 값으로 덮어써요**.
- **CSV**: 머리글 `week,channel,followers,reach,engagement_rate,link_clicks`, 최대 2000행. 틀린 행은 줄 번호와 이유(열 수 · 날짜 · 월요일 아님 · SNS 이름 · 숫자 · 같은 파일 안 중복)를 알려 줘요. 내보내기는 같은 모양이라 그대로 다시 가져올 수 있어요.
- **샘플 불러오기**: 가상의 8주 × 4 SNS = 32행. 샘플이 들어 있는 동안은 "샘플 데이터(가상)" 표시가 붙어요.
- **보여 주는 것**: 지표 4개(팔로워 · 리치 · 참여율 · 링크 클릭)의 주별 추이(최대 52주, SNS 별 선, 마지막 값 표시)와 **최신 주 비교**(직전 주 대비 · 최근 4주 중앙값 대비, 비교할 주가 없으면 그렇다고 써요).

## 4. ③ 수지·자금 시뮬레이션 (`/admin/finance/`)

기(期)별 가정(기업 수 · 프로젝트 수 · 성사율 · 수수료 · 광고 단가 · 비용)을 넣으면 연 합계 · 월별 곡선 · **흑자 전환 시기** · **자금 잔액** · **손익분기 기업 수**를 계산해요(`packages/core/src/adminFinance.ts`, 결과 문장은 `adminFinanceText.ts`).
금액은 모두 엔(円)이고, 1기는 12개월이며 1~5기까지 넣을 수 있어요.

### 4-1. 쓰는 순서

1. 처음에는 "サンプルを読み込む（仮想）"(가상의 3기 시나리오) 또는 "空のシナリオを作る"(빈 시나리오)를 골라요. 시나리오는 이름을 붙여 **여러 개** 저장돼요(복제 · 이름 변경 · 삭제, 최대 20개).
2. "前提を入力する"(가정 입력) 칸에 숫자를 넣어요. 입력하는 즉시 결과가 바뀌어요. 틀린 입력은 그 칸 아래에 이유를 적고, 맞는 값만 저장해요(샘플을 고치면 "샘플" 표시가 사라져요). 숫자는 전각 숫자와 쉼표도 읽어요.
3. 결과 · 그래프 · 표 · 민감도를 보고, 다른 시나리오와 겹쳐 비교하거나 JSON 으로 내보내요.

### 4-2. 입력 칸

| 칸 | 뜻 | 범위 |
| --- | --- | --- |
| 시나리오 이름 | 저장·비교할 때 쓰는 이름 | 1~60자 |
| 시작 시점의 기업 수 | 1기가 시작할 때의 참가 기업 수 | 0~1,000,000 (정수) |
| 기 이름 | 예: 1기 | 1~20자 |
| 기말 기업 수 | 그 기가 끝날 때의 참가 기업 수 | 0~1,000,000 (정수) |
| 기업당 프로젝트 수 | 기업 1곳이 한 기 동안 여는 프로젝트(챌린지) 수 | 0~1000 |
| 성사율 | 프로젝트 가운데 매칭(채용)이 성사되는 비율 | 0~100% |
| 건당 수수료 | 성사 1건의 중개 수수료 | 0~1조 엔 |
| 기부 비율 | 수수료 가운데 기부로 돌리는 비율 | 0~100% |
| 기업당 광고 단가 | 기업 1곳이 한 기 동안 내는 광고비 (소수 가능) | 0~1조 엔 |
| 매출원가 | 한 기의 매출원가 (없으면 0) | 0~1조 엔 |
| 경비 행 | 항목 이름(1~40자) + 한 기의 금액, 기마다 최대 30행 | 0~1조 엔 |
| 자기자본 · 차입 · 설비투자 | 시작 시점의 자금 | 0~1조 엔 |
| 기마다 상환액 | 차입금을 갚는 금액 (없으면 0) | 0~1조 엔 |

경비 행에는 **인건비 계산기**(인원 × 시급 × 주당 시간 × 연간 주 수)로 계산한 금액을 한 줄로 넣을 수 있어요.

### 4-3. 계산 방법

기마다(한 기 = 12개월의 합계):

- 성사 건수 = **반올림**(기말 기업 수 × 기업당 프로젝트 수 × 성사율) — 정수로 반올림해요(0.5 는 올려요).
- 수수료 매출 = 성사 건수 × 건당 수수료 × (1 − 기부 비율). 기부로 돌리는 몫(성사 건수 × 건당 수수료 × 기부 비율)은 매출에 넣지 않아요.
- 광고 매출 = 기말 기업 수 × 기업당 광고 단가. 매출 = 수수료 매출 + 광고 매출.
- 경상이익 = 매출 − 매출원가 − 경비 합계.
- 1사당 공헌이익 = 성사율 × 프로젝트 수 × 건당 수수료 × (1 − 기부 비율) + 광고 단가.
- **손익분기 기업 수** = (경비 합계 + 매출원가) ÷ 1사당 공헌이익을 올림한 정수. 공헌이익이 0 이하면 "없음", 비용이 0이면 0이에요. 성사 건수의 반올림은 반영하지 않은 근사예요.

월별 곡선(기마다 12개월):

- 기업 수는 기초(1기는 시작 시점의 기업 수, 그다음은 앞 기의 기말)에서 기말까지 **매달 같은 폭으로** 늘거나 줄어요. 12개월째가 기말 값이에요.
- 연 매출과 매출원가는 **월별 기업 수의 비율로 나눠요**(월 합계 = 연 값 그대로). 경비는 12등분해요.
- 시작 자금 = 자기자본 + 차입 − 설비투자. 월말 자금 잔액 = 시작 자금 + 누적 경상이익 − 누적 상환액. 상환은 기마다 상환액 ÷ 12 를 매달, 차입 총액을 넘지 않게 갚아요.

시점 찾기(±0.5엔 이내의 계산 오차는 0으로 봐요):

- **흑자 전환** = 월 경상이익이 그 달부터 끝까지 0 이상인 첫 달. **누적 손익이 플러스**가 되는 때도 같은 방식으로 찾아요.
- **자금 부족** = 자금 잔액이 처음 0 미만이 되는 달(시작 시점부터 모자라면 "시작 시점").
- 표시한 기간 안에서 일어나지 않는 일은 "오지 않는다"가 아니라 "표시한 기간(○기) 안에서는 …"이라고 써요.

### 4-4. 보여 주는 것

- **결과 요약**: 숫자 6개(흑자 전환 시기 · 마지막 기의 손익분기 기업 수 · 마지막 기의 매출 · 마지막 기의 경상이익 · 마지막 달의 자금 잔액 · 최저 자금 잔액과 그 시기)와 문장 5줄(흑자 전환 · 누적 플러스 · 자금 · 기마다의 손익분기 기업 수 · 마지막 달의 값).
- **그래프 4개**: 월별 누적 손익·자금 잔액(흑자 전환·자금 부족 표시선) · 월별 경상이익(흑자 전환 표시선) · 기별 매출·비용·경상이익 · 참가 기업 수 추이. 가로축은 시작 시점부터의 개월 수예요.
- **표**: 기별 연간 표(기업 수 · 성사 건수 · 수수료 매출 · 광고 매출 · 매출 · 매출원가 · 경비 · 경상이익 · 기부액 · 손익분기 기업 수, 합계 열 포함)와 접어 둔 월별 표(12개월 × 기 수만큼의 행).
- **민감도**: 성사율 · 건당 수수료 · 기업당 광고 단가 가운데 하나를 골라, **모든 기**의 값을 −30% ~ +30%(10%씩) 바꾼 7줄로 흑자 전환 · 자금 부족 · 마지막 기의 경상이익 · 마지막 달의 자금 잔액을 보여요(성사율은 0~100% 안으로 막아요). 지금 값(0%) 줄에 표시가 붙어요.

### 4-5. 시나리오 저장과 겹쳐 비교

- 시나리오는 이름을 붙여 따로 저장돼요(예: "제출판"과 "수정 시산"). 하나를 고르면 그 시나리오가 편집·계산돼요.
- **겹쳐 비교**: 저장한 시나리오 가운데 **다른 하나**를 골라 한 그래프에 겹쳐요. 실선 = 표시 중, 점선 = 비교할 시나리오. 비교할 값은 누적 손익 · 자금 잔액 · 월 경상이익 · 참가 기업 수 중에서 골라요. 기 수가 달라도 돼요(긴 쪽에 맞추고 짧은 쪽은 빈 칸). 두 시나리오의 흑자 전환·자금 요약이 한 줄씩 붙어요. 시나리오가 하나뿐이면 둘 이상 저장하라고 안내해요.

### 4-6. JSON 가져오기 · 내보내기

- 내보내기: `finance-scenario-<날짜>.json`. "예시 내려받기"는 가상의 예시(`finance-scenario-example.json`)를 내려받아요.
- 가져오기: 파일 선택(2MB 까지) 또는 붙여넣기 → **새 시나리오로 추가**돼요(이름이 겹치면 " (2)" 를 붙여요). 틀린 곳은 JSON 위치(예: `periods[1].matchRate`)와 이유를 목록으로 알려 주고(처음 10개 + "ほか"), 아무것도 추가하지 않아요.
- 읽을 때의 규칙: `schemaVersion` 은 `1`, 모르는 키는 무시, 글자 수 500,000 까지, 앞의 BOM 은 허용해요. 비율(`matchRate` · `donationRate`)은 JSON 에서 **0~1**(화면에서는 %)이에요.

| 키 | 필수 | 단위 · 범위 |
| --- | :-: | --- |
| `schemaVersion` | ✅ | `1` |
| `name` | ✅ | 1~60자 |
| `startCompanies` | 선택(기본 0) | 정수 0~1,000,000 |
| `periods` | ✅ | 1~5개의 기 (배열) |
| `periods[].label` | ✅ | 1~20자 |
| `periods[].companiesEnd` | ✅ | 정수 0~1,000,000 |
| `periods[].projectsPerCompany` | ✅ | 0~1000 |
| `periods[].matchRate` | ✅ | 0~1 |
| `periods[].feePerMatchYen` | ✅ | 엔, 0~1e12 |
| `periods[].donationRate` | ✅ | 0~1 |
| `periods[].adRevenuePerCompanyYen` | ✅ | 엔, 0~1e12 (소수 가능) |
| `periods[].costOfRevenueYen` | 선택(기본 0) | 엔, 0~1e12 |
| `periods[].costs` | ✅ | 최대 30개, 각각 `{ "label": 1~40자, "yen": 0~1e12 }` |
| `funding.equityYen` · `borrowingYen` · `capexYen` | ✅ | 엔, 0~1e12 |
| `funding.repaymentYenPerPeriod` | 선택(기본 0) | 엔, 0~1e12 |

### 4-7. 가정과 한계

- **시산 도구예요.** 세금 · 감가상각 · 운전자금 · 매출이 들어오는 시차는 다루지 않고, 경상이익을 그대로 현금의 증감으로 봐요. 자금 잔액은 그만큼 낙관적일 수 있어요.
- 한 기 안의 값(성사율 · 수수료 · 광고 단가 …)은 변하지 않는다고 봐요. 기업 수는 기초에서 기말까지 직선으로 늘고, 계절성·이탈은 따로 다루지 않아요.
- 자금(자기자본 · 차입 · 설비투자)은 시작 시점에 한 번에 들어오고 나가요. 이자는 계산하지 않아요(상환만 있어요).
- 입력은 **가정**이에요. 숫자가 틀리면 결과도 틀려요. 결과 문장과 그래프는 같은 계산(`simulate`)에서 나와서 서로 어긋나지 않아요.
- 한 브라우저에 20개까지만 저장해요(저장 용량을 지키려는 상한).

## 5. 만들지 않은 것 · 다음 단계

- 로그인과 운영자 권한: 지금은 누구나 주소로 들어올 수 있는 **데모**예요. 실서비스에서는 로그인 + 관리자 권한(DB `users` 의 역할)으로 막아야 해요.
- DB·서버 연결: ①은 데모 데이터를 세고, ②·③의 입력은 이 브라우저에만 있어요. 실서비스에서는 ①을 DB 뷰·집계(`analytics_daily` 등)로, ②를 각 SNS 의 API 로 바꿀 수 있지만 이번에는 하지 않았어요.
- 모바일 앱: 웹 전용이에요.
- 세금·감가상각·이자·운전자금·계절성: ③에서 다루지 않았어요(4-7).
